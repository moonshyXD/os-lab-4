# Лабораторная работа №4, вариант 1

Язык C11, Linux. Две программы: `parent` и `child`.
Основа — исходники `C:/Projects/os-labs/1/src` (ЛР №2, вариант 1).
Сохранены ввод, проверка `int`, подсчёт суммы в `long` с проверкой переполнения.
Вместо pipe используются файловое отображение `mmap(MAP_SHARED)` и сигналы.

## Сборка и запуск

```sh
make
cd src
./parent
```

Первая строка — имя выходного файла, следующие — целые числа:

```text
result.txt
1 2 3
10 -5 7
```

После запуска дочерней программы родитель выводит строку `parent PID=…, child PID=…`.
Пустая строка или EOF (Ctrl+D в Linux) завершает ввод. В `result.txt`:

```text
6
12
```

Запускайте `parent` из `src`: дочерний файл открывается по пути `./child`.
Существующий выходной файл перезаписывается, как во второй лабораторной.
Пробельная строка пропускается; ошибочная строка не записывается, следующие
строки обрабатываются, итоговый код завершения ненулевой. NUL во вводе — ошибка.
Диапазон каждого числа соответствует `int`, результат хранится в `long`.

## Обмен

1. До fork блокируются SIGUSR1/SIGUSR2/SIGCHLD. Маска сохраняется при exec.
2. Родитель создаёт временный файл с mkstemp, удаляет его имя и передаёт
   унаследованный дескриптор, имя результата и свой PID через аргументы exec.
3. Child открывает результат и сообщает о готовности сигналом SIGUSR2.
4. Parent задаёт размер файла под строку, отображает его, копирует строку с NUL,
   снимает отображение и посылает SIGUSR1.
5. Child отображает файл, проверяет строку и считает сумму, проверяет запись
   и fflush результата, снимает отображение и только затем отвечает SIGUSR2.
6. После подтверждения parent может менять размер. Нулевой размер означает EOF;
   child не вызывает mmap с нулевой длиной. Parent собирает статус через waitpid.

Стандартные сигналы не образуют очередь, поэтому допускается только одна
неподтверждённая команда. Ранняя доставка безопасна: сигнал заблокирован и
потребляется через sigwaitinfo/sigtimedwait. Ожидание ответа учитывает SIGCHLD.
Дочерний процесс периодически проверяет ожидаемый PID родителя, чтобы не остаться
ждать после его смерти. При локальной ошибке parent завершает child и вызывает waitpid.
Нет фиксированного лимита длины строки; размер ограничен доступными ресурсами ОС.
Во время ожидания ввода `pselect` временно разблокирует SIGCHLD. Если дочерний
процесс завершится или остановится, `waitid` проверит его состояние, а `waitpid`
заберёт статус. Родителю не нужно ждать следующей строки или EOF.

## Трассировка и отчёт

Из корня проекта запустите программу под `strace`:

```sh
make strace
```

Введите имя выходного файла и строки чисел, как при обычном запуске.
Имя файла результата отсчитывается от каталога `src`. После пустой строки
или EOF полная трасса находится в `strace.log` в корне проекта. Каждый
новый запуск `make strace` перезаписывает этот файл.

PDF пересобирается командой `make report` из корня проекта.
Результаты проверок перед сдачей сохранены в `report/inc/test-results.json`
и `report/inc/sanitizer-results.json`.

Лог запуска с PID и суммами: `report/inc/demo.txt`.
Полная трасса без фильтров: `report/inc/ipc-trace.txt`. Ключевые строки тех же PID: `report/inc/ipc-excerpt.txt`.
Отчёт с полными исходниками и трассой в приложениях: `report/report.pdf`;
редактируемый исходник: `report/report.tex`.

Сборка: GCC 13.3.0, Linux x86_64 / WSL2. Проверки на другой ОС не выполнялись.
